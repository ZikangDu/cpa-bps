# 糖果题基准

`candy-sub2api-v1` 保留用户本地 Sub2API 的 `backend/internal/service/pelican_scheduled.go` 中 `CandyPrompt` 原文、数表及换行，调用说明沿用“只输出最终答案数字，不要解释”。原始公开项目是 [haowang02/codex-candy-eval](https://github.com/haowang02/codex-candy-eval)。本模块自行实现判分，没有移植该项目的程序代码；本地 Sub2API 的 `candy_answer.go` 及其测试用于确认兼容行为。

请求只能使用 `DefaultPrompt` 与 `Instructions`。`DefaultExpectedAnswer`、`Explanation` 只在本地评分及展示，不发送给模型。历史结果需要保存 `Version`；修改题面、数表或判分语义时应更新版本。

## 数学核验及题面歧义

标准答案为 21，前提是能凭触感挑选形状、无法辨认口味且取出后不放回。原题隐含了“能挑形状”，默认提示不额外强调它，以保持与 Sub2API 的横向可比性。

记圆形和星形取出数量为 `(r,s)`。若没有苹果/桃子异形配对，所有取出组合一定落在以下四个区域之一：

- `(r <= 24, s <= 4)`：星形仅取西瓜，圆形可任取。
- `(r <= 8, s <= 17)`：圆形仅取西瓜，星形可任取。
- `(r <= 15, s <= 11)`：两种形状均只取苹果或西瓜。
- `(r <= 17, s <= 10)`：两种形状均只取桃子或西瓜。

`(9,12)` 不在任何失败区域内，因此 21 足够。总数不超过 20 时，若 `r <= 8` 则在第二个区域；若 `9 <= r <= 15` 则 `s <= 11`，在第三个区域；若 `r >= 16` 则 `s <= 4`，在第一个区域。因此更少不够。测试独立穷举六类糖果的所有合法数量，核对四个区域及最小值。

若不允许挑形状，取出 24 颗圆形与 4 颗星形西瓜仍失败，共 28 颗，此时保证成功需要 29。单题结果不能证明模型身份、整体能力或长期质量，推理 token 数量不参与判分。

## 判分约定

`ParseGrade(answer, expected)` 返回 `pass` 或 `answer_fail`，以及规范化数字和固定原因码。调用方必须把请求错误、超时、响应解析错误与答案评分分开。

接受完整短答案，或最后一个非空行的独立短答案；此前明确的答案声明必须一致。接受 `21`、`21颗糖果`、`答案是21`、`最终答案：21`、`Answer: 21`、`The answer is 21`、`二十一`，以及整个答案或数字两端成对的常见 Markdown/引号。解释里的普通数字不会触发通过；相互矛盾的答案声明、多选答案、没有最终答案及声称“标准答案/expected answer”的元数据均拒绝。该规则采取保守判定，模糊输出可能记为无法解析，不做语义猜测。

输入上限是 65,536 字节，超限整段拒绝，不截断后评分。仅转换全角十进制数字、全角冒号和 CR/CRLF 换行；拒绝无效 UTF-8、不可见格式字符及非换行/回车/制表控制字符。不会合并数字间空格，不将 `2 1` 或 `2**1` 当作 `21`。十进制最多 9 位，允许前导零；不接受负数、小数、指数或分隔数字。中文数字只为该固定题兼容“二十一”；调用方给定的 `expected` 必须是至多 9 位十进制整数。最终行之外相互冲突的短答案或显式答案也会失败，因此不会通过在答案末尾附加正确数字来覆盖矛盾结论。
